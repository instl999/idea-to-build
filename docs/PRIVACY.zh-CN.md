# 隐私与数据处理

[English](PRIVACY.md) | **简体中文**

## 处理的数据

插件可能处理产品想法、研究查询/结果、需求、假设、核心/设计/live 文档、生成提示词、项目相对路径、Git 元数据、测试命令/结果和保护日志。它不需要账号、API key、远程插件后端或遥测。

大部分处理在本地。实时研究使用宿主 Web Search，因此查询文字和提供方常规元数据可能按宿主/提供方策略在仓库外处理。发布到 GitHub 的内容会交给 GitHub。

## 输入与检索前规则

- 不要粘贴秘密、凭据、私钥、`.env`、健康/金融/政府标识符、原始客户记录或机密源文。
- 将查询缩减到决策所需的最少事实；身份不必要时，用稳定假名替换姓名、邮箱、组织、仓库、域名和精确数字。
- 处理他人/组织数据前先取得授权。
- 优先使用聚合/示例数据和官方公开来源，只保存决策所需证据。
- 审查生成提示词：其中的需求可能在多个任务中重复。

## 存储与保留

生成项目把数据保存为普通本地 UTF-8/JSON/Markdown 和 Git 历史。`.idea-to-build/guardrail.log`、`last_test.json` 默认被忽略，但可能留在本机。删除工作文件不会自动清除 Git 历史、备份、工作树、远程 fork、Web Search 提供方日志或已经分享的提示词。

根据数据选择保留周期与访问控制；必要时使用仓库权限、加密存储、短期工作树和组织管理的安全删除/轮换流程。核心 hash 不是加密，也不提供保密性。

## 公开发布脱敏

使用合成夹具；审查完整 Git 历史而非仅当前文件；配置 no-reply 提交邮箱；清除私人路径和个人地址；泄露凭据必须轮换，不能只删除文字。运行：

```bash
python scripts/audit_public_release.py
```

该审计是启发式辅助。还应启用宿主 secret scanning/push protection 并人工复核。若敏感数据进入 GitHub，应立即撤销/轮换，按宿主流程清除 Git 对象/缓存/fork，并依据政策或法律通知受影响方。
