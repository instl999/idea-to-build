# 隐私与数据处理

[English](PRIVACY.md) | **简体中文**

## 处理的数据

插件可能处理产品想法、研究查询/结果、需求、假设、核心/设计/live 文档、生成提示词、项目相对路径、Git 元数据、测试命令/结果和保护日志。它不需要账号、API key、远程插件后端或遥测。

大部分处理在本地。实时研究使用宿主 Web Search，因此查询文字和提供方常规元数据可能按宿主/提供方策略在仓库外处理。发布到 GitHub 的内容会交给 GitHub。

## 输入与检索前规则

- 不要粘贴秘密、凭据、私钥、`.env`、健康/金融/政府标识符、原始客户记录或机密源文。
- 将查询缩减到决策所需的最少事实；身份不必要时，用稳定假名替换姓名、邮箱、组织、仓库、域名和精确数字。
- 处理他人/组织数据前先取得授权。
- 优先使用聚合/示例数据和官方公开来源，只保存决策所需证据。
- 审查生成提示词：其中的需求可能在多个任务中重复。

## 子智能体提示词最小化

生成或发送子智能体提示词前，只包含该工作流需要的冻结约束和范围上下文。不要重复原始研究转录、凭据、个人记录、专有源码片段或无关组织信息。子智能体/工作树执行使用宿主与本地 Git 权限；如果模型在远程处理数据，适用的是宿主数据政策，而不是插件自建后端政策。

## 下游 MCP 指导

生成产品考虑 MCP 时，候选元数据、配置示例、工具/资源描述和 server 输出都按不可信项目数据处理。不得把凭据或原始敏感记录写入台账、核心/设计文档、提示词、测试夹具或 Git；使用目标宿主认可的秘密存储、最小权限 scope、合成验证数据，并让高影响工具保留显式确认。

Idea-to-Build 不连接所推荐的 server，也不管理其数据保留。任何 server 侧传输、日志、保留、子进程或远程模型行为，都属于生成产品需审查的架构以及所选 server/宿主政策。

## 存储与保留

生成项目把数据保存为普通本地 UTF-8/JSON/Markdown 和 Git 历史。项目模板包含 `.gitignore`，默认忽略 `.idea-to-build/guardrail.log`、`last_test.json`、Python 缓存、本地虚拟环境和 `.env*`，同时保留 `.env.example`。既有项目和显式强制添加的文件仍需人工检查。删除工作文件不会自动清除 Git 历史、备份、工作树、远程 fork、Web Search 提供方日志或已经分享的提示词。

根据数据选择保留周期与访问控制；必要时使用仓库权限、加密存储、短期工作树和组织管理的安全删除/轮换流程。核心 hash 不是加密，也不提供保密性。

## 公开发布脱敏

使用合成夹具；通过仓库托管平台或独立历史扫描器检查当前文件和历史 blob；配置 no-reply 提交邮箱；清除私人路径和个人地址；泄露凭据必须轮换，不能只删除文字。再运行仓库辅助脚本：

```bash
python scripts/audit_public_release.py
```

该辅助脚本是启发式的：完整模式检查当前 tracked 文本和所有 refs 的 author/committer 邮箱，不检查 untracked 文件或历史 blob 内容。还应启用宿主 secret scanning/push protection 并人工复核。若敏感数据进入 GitHub，应立即撤销/轮换，按宿主流程清除 Git 对象/缓存/fork，并依据政策或法律通知受影响方。
